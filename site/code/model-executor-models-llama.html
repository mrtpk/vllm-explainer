"model_executor/models/llama.py: the Llama model"

Purpose#

vllm/model_executor/models/llama.py implements the Llama architecture with vLLM layers, so that the worker can build it, load a Hugging Face checkpoint into it, and run it in the forward pass of each step.

Filevllm/model_executor/models/llama.py, 585 lines of Python. The header says it is adapted from the Transformers Llama code, v4.28.0 (vllm/model_executor/models/llama.py:4-5).
Main classLlamaForCausalLM (vllm/model_executor/models/llama.py:464-561).
Runs inEach worker (one per GPU), or the engine core process with the uni executor. Built once in load_model; forward runs on the GPU in every step, usually inside a compiled graph or a CUDA graph.
Called byThe model loader through initialize_model() after the registry resolves the name (vllm/model_executor/model_loader/utils.py:96-103); Model Runner V2 for forward and compute_logits (vllm/v1/worker/gpu/model_runner.py:2070, vllm/v1/worker/gpu/model_runner.py:1638); 21 other files that import it.
CallsThe TP layers of linear.py and vocab_parallel_embedding.py, Attention, RMSNorm, get_rope, SiluAndMul, LogitsProcessor, and the helpers make_layers, AutoWeightsLoader and WeightsMapper (vllm/model_executor/models/llama.py:35-79).
Not in this fileHow the layers split and communicate (The tensor-parallel layers (linear.py and vocab_parallel_embedding.py)), the attention kernels (Attention backends: backend, metadata builder and implementation), compilation (torch.compile and CUDA graphs in vLLM), the registry lookup (model_executor/models/registry.py: the model registry).

The page How a vLLM model file is written (llama.py) explains the patterns of this file. This page reads the file class by class and follows the load_weights path.

Where it sits#

Who calls it#

  • The registry. Nine names map to this file, seven of them to LlamaForCausalLM: LlamaForCausalLM, LLaMAForCausalLM, InternLM3ForCausalLM, IQuestCoderForCausalLM, TeleChat3ForCausalLM, and the embedding names LlamaModel and MistralModel (vllm/model_executor/models/registry.py:140-155, vllm/model_executor/models/registry.py:212, vllm/model_executor/models/registry.py:231-238). Two more map to the bidirectional wrappers (vllm/model_executor/models/registry.py:230, vllm/model_executor/models/registry.py:326-329). (Counts from an evaluation of the tables.)
  • The loader. initialize_model() builds the class; the default loader calls load_weights() (vllm/model_executor/model_loader/default_loader.py:503).
  • The model runner. Each step calls the model with input_ids, positions, inputs_embeds and intermediate_tensors (vllm/v1/worker/gpu/model_runner.py:1984-2009), then compute_logits() on the sampled rows.
  • Other model files. For example MistralForCausalLM, Phi3ForCausalLM and TeleChat2ForCausalLM subclass LlamaForCausalLM (vllm/model_executor/models/mistral.py:236, vllm/model_executor/models/phi3.py:10, vllm/model_executor/models/telechat2.py:107).

What it calls#

  • QKVParallelLinear, MergedColumnParallelLinear, RowParallelLinear (vllm/model_executor/models/llama.py:45-49), VocabParallelEmbedding and ParallelLMHead (vllm/model_executor/models/llama.py:53-56).
  • Attention or EncoderOnlyAttention (vllm/model_executor/models/llama.py:39-42).
  • CustomOps: RMSNorm, SiluAndMul, and the rotary embedding from get_rope (vllm/model_executor/models/llama.py:38, vllm/model_executor/models/llama.py:44, vllm/model_executor/models/llama.py:52).
  • maybe_fused_act_quant, which can fuse the activation with the quantization of the next layer's input (vllm/model_executor/models/llama.py:43, vllm/model_executor/models/llama.py:120).
  • Helpers from models/utils.py and mixins from models/interfaces.py (vllm/model_executor/models/llama.py:61-79).

Walk through the main methods#

LlamaAttention.__init__: sliding windows and the attention class#

The head arithmetic and the two linear layers are on How a vLLM model file is written (llama.py) (lines 143-181). The second half of the constructor:

  1. Line 183. _init_rotary_emb calls get_rope with the head size, max_position_embeddings and the config's rope_parameters, NeoX style (lines 236-248).
  2. Lines 186-204. If the config has layer_types, a layer marked sliding_attention gets config.sliding_window. The layer index comes from the prefix (line 141). For an EAGLE-3 draft, the index is shifted by target_layer_count.
  3. Lines 206-210. ENCODER_ONLY selects EncoderOnlyAttention; everything else uses Attention.
  4. Lines 212-222. The attention layer gets per-rank heads (self.num_heads, self.num_kv_heads), the scale head_dim ** -0.5 (line 162) and its prefix.

LlamaDecoderLayer: config knobs and the residual#

  1. Line 263. The quant config comes from get_quant_config(), which subclasses can override (lines 332-334).
  2. Lines 268-274. attention_bias or bias turns on biases in QKV and o_proj; qkv_bias sets the QKV bias alone. The comments name the models that need this.
  3. Lines 280-283. is_causal=False in the config makes the layer bidirectional, for embedding models.
  1. Lines 320-322. The first layer has no residual yet: it keeps the input as the residual and normalizes.
  2. Line 324. Later layers call the norm with the residual. RMSNorm adds it and normalizes in one op, and returns the new residual too.
  3. Line 328. The same fused add-and-norm before the MLP. The layer returns (hidden_states, residual); the final norm of LlamaModel adds the last residual (line 452).

LlamaModel.load_weights and LlamaForCausalLM.load_weights: the load path#

Follow one tensor, model.layers.0.mlp.up_proj.weight, in a TP = 2 worker:

  1. The default loader calls LlamaForCausalLM.load_weights(iterator) (vllm/model_executor/model_loader/default_loader.py:503).
  2. The outer AutoWeightsLoader has no model mapper. It adds the quant config mappers, if any, and the rule that drops old rotary tables (vllm/model_executor/models/utils.py:460-473).
  3. The walk groups by model and finds self.model, a LlamaModel with its own load_weights. It passes the rest of the name: layers.0.mlp.up_proj.weight (vllm/model_executor/models/utils.py:387-400).
  4. LlamaModel.load_weights makes a second AutoWeightsLoader with hf_to_vllm_mapper. .up_proj becomes .gate_up_proj with shard id 1 (vllm/model_executor/models/llama.py:354-355).
  5. The walk goes layers → 0 → mlp → gate_up_proj. MergedColumnParallelLinear has a load_weights; it reads shard_id = 1 from the tensor and calls the parameter's loader (vllm/model_executor/layers/linear.py:985-1000).
  6. The v2 loader computes offset 14336 / 2 = 7168 and size 7168 in the parameter. It copies checkpoint rows rank × 7168 to rank × 7168 + 7167 (vllm/model_executor/layers/linear.py:965-983, vllm/model_executor/parameter.py:153-173).
  7. The loaded name goes back up the tree with its prefixes: model.layers.0.mlp.gate_up_proj.weight. The default loader uses the set of these names for its completeness check (vllm/model_executor/model_loader/default_loader.py:510-523).

The tensor lm_head.weight takes another path. In the outer walk, lm_head is a ParallelLMHead without load_weights, so its weight parameter uses VocabParallelEmbedding.weight_loader (vllm/model_executor/models/utils.py:416-424). If tie_word_embeddings is set, lm_head.weight is the same object as model.embed_tokens.weight (lines 509-510), and the loader skips the second name (vllm/model_executor/models/utils.py:255-259). One exception: if the config says tied but the checkpoint has its own lm_head, VllmConfig turns the flag off, so the head loads (vllm/config/vllm.py:1594-1599). After loading, vLLM ties the two again if they are equal (vllm/config/model.py:1255-1281, vllm/model_executor/model_loader/utils.py:155).

LlamaForCausalLM: class attributes#

  1. Lines 464-472. The mixins; How a vLLM model file is written (llama.py) has a table of what each one adds.
  2. Line 473. The outer class shares the mapper of LlamaModel. SupportsQuant.__new__ gives its rename-only part to the quant config, so names in ignored_layers can match vLLM names (vllm/model_executor/models/interfaces.py:1292-1299). For Llama this part is empty: get_rename_mapper() drops the stacked rules, which are the only rules of this mapper (vllm/model_executor/models/utils.py:180-199).
  3. Lines 475-478. packed_modules_mapping tells LoRA and the quant config which checkpoint layers form each stacked layer.
  4. Lines 479-482. embedding_modules lists the layers that get LoRA embedding buffers; Mistral clears it (vllm/model_executor/models/mistral.py:237-238).

Deep dive

Interaction with other subsystems

  • Forward context. Each Attention registers under its prefix, for example model.layers.0.self_attn.attn (vllm/model_executor/layers/attention/attention.py:443-445). See The forward context: how layers find per-step data.
  • torch.compile. Only LlamaModel.forward is compiled (vllm/model_executor/models/llama.py:337-346); the attention call is an opaque custom op on CUDA-like platforms (vllm/model_executor/layers/attention/attention.py:436-440).
  • LoRA. The LoRA manager wraps the linear layers that it finds with named_modules(); packed_modules_mapping maps qkv_proj to the three LoRA targets (vllm/model_executor/models/llama.py:475-478). The names in embedding_modules (lines 479-482) also count as supported LoRA modules (vllm/lora/utils.py:251-254).
  • Speculative decoding. EAGLE-3 sets the layers whose hidden states EagleModelMixin collects (lines 427-441); with PP they travel in IntermediateTensors under aux_hidden_states_<i> (vllm/model_executor/models/interfaces.py:1652-1661). spec_decode_needs_target_embed keeps a real embedding on the last PP stage for some drafters (vllm/model_executor/models/utils.py:863-883).
  • Pooling. The bidirectional classes reuse the whole file through the adapters as_seq_cls_model and as_embedding_model (lines 564-571).

Check yourself#

  1. 1
    Which class of llama.py carries @support_torch_compile?
    easy
    Show answer

    LlamaModel (vllm/model_executor/models/llama.py:337-347). LlamaForCausalLM.forward only calls it.

  2. 2
    Why does LlamaForCausalLM.load_weights pass no mapper, although the class has hf_to_vllm_mapper?
    medium
    Show answer

    The outer loader hands every model.* tensor to LlamaModel.load_weights, which applies the mapper itself (vllm/model_executor/models/utils.py:387-400, vllm/model_executor/models/llama.py:459-461). The class attribute on the outer class is for others: SupportsQuant gives its rename part to the quant config (vllm/model_executor/models/interfaces.py:1296-1297). For Llama that part is empty, because the mapper has only stacked rules (vllm/model_executor/models/utils.py:186-196).

  3. 3
    A config has "qkv_bias": true and no attention_bias. Which layers get a bias?
    medium
    Show answer

    Only qkv_proj. bias_o_proj takes the value of attention_bias before qkv_bias overrides attention_bias (vllm/model_executor/models/llama.py:268-274).

  4. 4
    Follow model.layers.0.mlp.gate_proj.weight on TP rank 1 of a Llama-3-8B with TP = 2. Which rows of the checkpoint tensor end up where?
    hard
    Show answer

    The mapper renames it to layers.0.mlp.gate_up_proj.weight with shard id 0 (vllm/model_executor/models/llama.py:354). The v2 loader uses offset 0 and size 14336 / 2 = 7168 in the parameter (vllm/model_executor/layers/linear.py:967-970). The parameter copies checkpoint rows 7168-14335 (rank 1 × 7168) into its rows 0-7167 (vllm/model_executor/parameter.py:168-173).

Related pages

  • How a vLLM model file is written (llama.py)A vLLM model file rebuilds the Hugging Face architecture from vLLM layers. Every constructor takes vllm_config and a prefix, linear layers are tensor-parallel, attention is an Attention layer object, and pipeline stages use PPMissingLayer and IntermediateTensors. llama.py is the example.
  • "Weight loading: from checkpoint files to GPU parameters"Each worker picks a model loader by --load-format, builds the model with empty per-rank parameters on its GPU, streams every checkpoint tensor once, renames it with a WeightsMapper, and lets the parameter's weight_loader copy only this rank's slice.
  • The tensor-parallel layers (linear.py and vocab_parallel_embedding.py)vLLM's linear and embedding layers know their tensor-parallel rank. They resolve a quantization method per layer, allocate only their slice, cut checkpoint tensors when they load, and call the all-reduce or all-gather in forward. QKVParallelLinear splits by heads and copies KV heads when TP is larger than their count.
  • Model capability protocols (SupportsPP, SupportsLoRA, ...)A model class tells vLLM what it can do through base classes from models/interfaces.py. Detector functions turn them into a _ModelInfo record, and start-up checks use that record to allow or reject PP, LoRA, multimodal input and more.
  • "model_executor/layers/linear.py: tensor-parallel linear layers"vllm/model_executor/layers/linear.py holds LinearBase and the replicated, column-parallel, merged-column, QKV and row-parallel linear layers. Each one resolves a quantize method, allocates its per-rank weight through it, cuts checkpoint tensors in weight_loader or weight_loader_v2, and calls the TP all-gather or all-reduce in forward.
  • model_executor/models/registry.py: the model registryvllm/model_executor/models/registry.py holds the tables of built-in architectures, the _ModelInfo capability record, eager and lazy registry entries with a disk cache, the lookup order from architecture name to class, and the inspection subprocess.
  • The forward context: how layers find per-step dataAttention layers register themselves by name when the model is built, get their KV cache tensor bound at start-up, and read the per-step metadata from a global forward context that the model runner sets around each forward pass. The attention custom ops take only the layer name, so torch.compile sees them as opaque.
