vllm serve flags

Referenceabout 65 min read

Code version: vLLM @ 3e44c0d · 2026-10-22

In one sentence

Almost every vllm serve flag is one field of a config dataclass; many flag defaults are None, and EngineArgs computes the real value later.

Use this page in two ways. To learn how the parser works and which defaults are real, read the first four sections. To look up one flag, go to All flags, or search for its name. The script tools/gen_serve_flags.py makes the big tables from the parser code. The text above the tables is written by hand from the code.

How a config field becomes a flag#

vllm serve builds its parser in make_arg_parser. It adds five arguments by hand: the positional model_tag, --headless, --api-server-count, --config and --grpc. Then it adds the front-end flags and the engine flags (vllm/entrypoints/common/cli_args.py:429-466):

The engine flags come from EngineArgs.add_cli_args. For each config class, it calls get_kwargs(XConfig), makes one argument group with the class name as its title, and adds one flag per field. The flag name is written by hand. The type, default, choices and help come from the field. Sometimes the code replaces the field default. In this excerpt, three scheduler flags get the default None:

get_kwargs returns a copy of the cached result of _compute_kwargs (vllm/engine/arg_utils.py:324, vllm/engine/arg_utils.py:443-453). _compute_kwargs reads each dataclass field (vllm/engine/arg_utils.py:324-440):

  • Default: the field default, or the result of its default factory (vllm/engine/arg_utils.py:339-352).
  • Help: the string literal after the field, read by get_attr_docs (vllm/engine/arg_utils.py:355-356, vllm/config/utils.py:201-215). The parser reads these strings only when the command line contains --help (or when mkdocs is loaded), because that is slow (vllm/engine/arg_utils.py:285-288, vllm/engine/arg_utils.py:327).
  • Type: from the type hint. A dataclass type takes JSON. A bool gets BooleanOptionalAction (a bool | str | None field takes an optional text value instead). A Literal gives the choices. A list, tuple or set takes several values. Some int fields accept 1k, 2M or 1G (vllm/engine/arg_utils.py:367-425).

Flag pairs: --enable-x and --disable-x#

FlexibleArgumentParser replaces BooleanOptionalAction with EnableDisableAction (vllm/utils/argparse_utils.py:179). For a flag that starts with --enable-, it adds the opposite --disable- flag, and the reverse. The form --no-enable-x still works, but --help does not show it (vllm/utils/argparse_utils.py:120-151). Other boolean flags get the normal pair, for example --enforce-eager and --no-enforce-eager.

Other parser rules#

  • Dashes and underscores. --max_num_seqs and --max-num-seqs are the same flag. The parser changes _ to - in the flag name (vllm/utils/argparse_utils.py:374-394).
  • JSON flags. A flag that takes a dataclass also accepts its keys one by one, for example -cc.mode=3 (vllm/config/vllm.py:405-406, vllm/utils/argparse_utils.py:462-491).
  • Optimization level. -O3 is short for --optimization-level 3 (vllm/utils/argparse_utils.py:395-399).
  • Config file. --config file.yaml reads flags from a YAML file (vllm/utils/argparse_utils.py:371-372).
  • Help by group. --help=ModelConfig shows one group, and --help=all shows all flags (vllm/utils/argparse_utils.py:384-386, vllm/utils/argparse_utils.py:241-252).

The model: positional, not --model#

Give the model as the first positional argument: vllm serve Qwen/Qwen3-0.6B. The positional value goes into args.model (vllm/entrypoints/cli/serve.py:55-57). If you write --model X, the parser logs a warning that the option will be removed, and moves X to the front (vllm/utils/argparse_utils.py:324-353). With no model, the default is Qwen/Qwen3-0.6B (vllm/config/model.py:155). vllm serve --help does not list --model, because add_cli_args skips it when the command line contains both serve and --help (vllm/engine/arg_utils.py:961-962).

How the flags reach VllmConfig#

  1. AsyncEngineArgs.from_cli_args(args) copies each parsed value into the EngineArgs field of the same name (vllm/entrypoints/launchers/api_server/entry.py:52, vllm/engine/arg_utils.py:1962-1970).
  2. create_engine_config(usage_context=OPENAI_API_SERVER) builds the sub-configs (vllm/entrypoints/launchers/api_server/entry.py:82). On the way, it replaces the None defaults. Chunked prefill and prefix caching come from the model (vllm/engine/arg_utils.py:2275), and the scheduler limits come from the GPU memory (vllm/engine/arg_utils.py:2631-2635).
  3. It makes one VllmConfig (vllm/engine/arg_utils.py:2870). VllmConfig.__post_init__ checks the sub-configs together and sets more defaults, for example the compilation mode and async scheduling. See Config classes and How configuration works.

So the generated table below shows the default of the flag. For many tuning flags that is None, which means "EngineArgs or VllmConfig decides". The next section gives the values that they decide.

Simplified

The table gives the defaults for vllm serve (usage context OPENAI_API_SERVER, vllm/entrypoints/launchers/api_server/entry.py:72). The offline LLM class gets larger token budgets: 16384, 16384 and 8192 in the three memory tiers (vllm/engine/arg_utils.py:2963, vllm/engine/arg_utils.py:2977, vllm/engine/arg_utils.py:2987). Deprecated flags#

Three flags still parse, but they do nothing or forward to a new flag. The help text says that they will be removed in v0.33.0.

--api-key guards only four path prefixes

The help column below shows only the first sentence of the --api-key docstring. The rest of the docstring warns that the key does not guard every route (vllm/entrypoints/common/cli_args.py:326-336). The middleware checks only paths that start with /v1, /v2, /inference or /cohere (vllm/entrypoints/serve/middleware/authenticate.py:11, vllm/entrypoints/serve/middleware/authenticate.py:59-61). /invocations and /ping are on every server and answer without a key (vllm/entrypoints/launchers/api_server/routers.py:40-44). /generative_scoring, the pooling routes (/pooling, /classify, /score, /rerank) and /scale_elastic_ep are also outside the guarded prefixes. The page The OpenAI-compatible server: launch modes, app, serving classes and streaming lists them with their sources.

All flags#

Limits of the generated table

The script rebuilds the parser from the source with Python's ast module. It does not import vLLM. This has four results:

  • Plugins and platforms can add or change flags at run time (vllm/engine/arg_utils.py:3243, vllm/engine/arg_utils.py:3257). The table does not show these changes.
  • Choices that the code computes at run time show as source text.
  • Defaults are source text, for example CompilationConfig(). An envs.X default depends on the environment.
  • The help column has only the first paragraph of the field docstring. It does not show the text that the code appends.

The docstring of the script lists all limits.

Check yourself#

  1. 1
    You start vllm serve with --no-enable-prefix-caching. Does it work? Which form does --help show?
    easy
    Show answer

    It works. EnableDisableAction keeps the --no- form for old scripts, but hides it from the help. The help shows --enable-prefix-caching and --disable-prefix-caching (vllm/utils/argparse_utils.py:120-145).

  2. 2
    You serve a decoder model on one GPU with 48 GiB of memory and set no scheduler flags. What are max_num_seqs and max_num_batched_tokens? And with --performance-mode throughput?
    medium
    Show answer

    48 GiB is below 70 GiB, so the defaults are 256 requests and 2048 tokens (vllm/engine/arg_utils.py:2984-2992). Throughput mode doubles both values that you did not set: 512 and 4096 (vllm/engine/arg_utils.py:3171-3175). Chunked prefill is on for this model, so the max_model_len floor does not apply (vllm/engine/arg_utils.py:3181-3186).

  3. 3
    The generated table says that the default of --enable-chunked-prefill is None, and SchedulerConfig says True. For a Whisper-style encoder-decoder model, is chunked prefill on?
    hard
    Show answer

    No. EngineArgs.add_cli_args passes None, and _set_default_chunked_prefill_and_prefix_caching_args replaces it with model_config.is_chunked_prefill_supported (vllm/engine/arg_utils.py:3031-3035). That property returns False for a generative encoder-decoder model (vllm/config/model.py:2229-2233). So vllm serve never uses the dataclass value True (vllm/config/scheduler.py:134).
