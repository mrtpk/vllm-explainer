--- title: distributed/parallel_state.py: process groups and GroupCoordinator nav_title: distributed/parallel_state.py level: Advanced prerequisites: concepts/distributed-groups related: concepts/distributed-groups, concepts/tp-layers, concepts/expert-parallel-moe, concepts/data-parallel-serving, code/distributed-device-communicators-shm-broadcast, code/v1-worker-gpu-worker, code/v1-executor-multiproc-executor, tours/multi-gpu-step summary: vllm/distributed/parallel_state.py builds the world group and the model-parallel groups (TP, PP, DP, EP, PCP, DCP, EPLB, ...) of each worker, wraps each in a GroupCoordinator, registers the collectives as torch custom ops, and tears everything down at shutdown. ---

Purpose

vllm/distributed/parallel_state.py owns the {{term process-group | process groups}} of a worker process: it creates them from the {{term rank-layout}}, keeps them in module globals such as _TP, and gives model code one object per group, the {{term group-coordinator}}, with all collectives.

Where it sits

Who calls it

  • The GPU worker, in init_device, before the memory snapshot ({{cite vllm/v1/worker/gpu_worker.py:497-507}}). Its helper calls set_custom_all_reduce, init_distributed_environment and ensure_model_parallel_initialized in that order ({{cite vllm/v1/worker/gpu_worker.py:1694-1716}}).
  • Model layers call the getters at construction and the collectives at run time, for example RowParallelLinear through tensor_model_parallel_all_reduce ({{cite vllm/model_executor/layers/linear.py:1803-1806}}, {{cite vllm/distributed/communication_op.py:12-14}}).
  • Model Runner V2 wraps CUDA graph capture in graph_capture, and the worker uses the PP group for isend_tensor_dict/irecv_tensor_dict ({{cite vllm/v1/worker/gpu_worker.py:1336-1347}}).
  • Shutdown: the worker process calls destroy_model_parallel and destroy_distributed_environment ({{cite vllm/v1/executor/multiproc_executor.py:824-833}}); the engine core calls cleanup_dist_env_and_memory ({{cite vllm/v1/engine/core.py:837-839}}).

What it calls

  • torch.distributed.init_process_group for the world, then new_group twice per group: device backend and gloo ({{cite vllm/distributed/parallel_state.py:1973-1982}}, {{cite vllm/distributed/parallel_state.py:501-518}}).
  • current_platform.get_device_communicator_cls(), only for groups with more than one rank ({{cite vllm/distributed/parallel_state.py:549-560}}).
  • MessageQueue.create_from_process_group for the groups that ask for a broadcaster ({{cite vllm/distributed/parallel_state.py:562-567}}).
  • direct_register_custom_op for all_reduce, reduce_scatter, all_gather and a patched scaled-matmul reduce-scatter, at import time ({{cite vllm/distributed/parallel_state.py:399-425}}).

Walk through the main methods

GroupCoordinator.__init__: two PyTorch groups per row

  1. Lines 498-499. Optional timeouts for the device and CPU groups (from --distributed-timeout-seconds and its CPU twin).
  2. Lines 501-512. For every row of group_ranks, the process makes a device group and a gloo group. new_group is collective, so all ranks must make all rows in the same order, even rows they are not in.
  3. Lines 513-518. The process keeps the pair for its own row, and records its rank inside the group.

The class comment shows the difference between rank, local_rank and rank_in_group with a 4-rank group over two nodes ({{cite vllm/distributed/parallel_state.py:436-449}}). With VLLM_DISTRIBUTED_USE_SPLIT_GROUP=1, the groups come from PyTorch split_group instead ({{cite vllm/distributed/parallel_state.py:480-491}}). The rest of the constructor picks the device, then adds the optional parts:

  1. Lines 549-559. A device communicator only for more than one rank. use_all2all is passed through; the communicator honours it only for groups named ep ({{cite vllm/distributed/device_communicators/base_device_communicator.py:244-245}}).
  2. Lines 563-567. The broadcaster: a MessageQueue of 6 chunks × 4 MiB, writer = the group's first rank.
  3. Lines 571-573. use_custom_op_call decides whether the collectives go through torch.ops.vllm.*.

all_reduce and friends

  1. Lines 740-741. A group of one returns the input; no kernel runs.
  2. Lines 743-746. The registered op takes the group's unique name (a string), because Dynamo cannot pass the Python object. The op body looks the group up in _groups ({{cite vllm/distributed/parallel_state.py:199-204}}).
  3. Lines 748-751. The real work is in the device communicator; without one this raises "No device communicator found".

all_gather and reduce_scatter follow the same pattern and check the dim argument ({{cite vllm/distributed/parallel_state.py:753-798}}). gather, all_gatherv and reduce_scatterv go straight to the communicator ({{cite vllm/distributed/parallel_state.py:774-838}}). broadcast uses torch.distributed.broadcast on the device group ({{cite vllm/distributed/parallel_state.py:840-853}}); broadcast_object prefers the shared-memory broadcaster ({{cite vllm/distributed/parallel_state.py:855-877}}).

isend_tensor_dict and irecv_tensor_dict: the PP hand-off

  1. Line 1211. Clean up finished earlier sends before posting new ones.
  2. Line 1212. The metadata (keys, dtypes, shapes, plain values) goes first, pickled on the gloo group by isend_object.
  3. Lines 1219-1222. The all-gather trick: with all_gather_group (the TP group), each TP rank sends only its 1/TP slice; the receiver rebuilds the full tensor with an all-gather.
  4. Lines 1224-1229. Each tensor goes by isend on the device group (CPU tensors on gloo). record_stream keeps the CUDA memory alive until the send finishes.
  5. Lines 1240-1243. The handles are also kept in _pending_isends, so a caller may drop them safely.

The receiver posts irecv for each tensor and returns post-processing callbacks for the all-gather case ({{cite vllm/distributed/parallel_state.py:1285-1369}}). The worker uses exactly this pair with all_gather_group=get_tp_group() ({{cite vllm/v1/worker/gpu_worker.py:1336-1347}}, {{cite vllm/v1/worker/gpu_worker.py:1372-1378}}).

init_distributed_environment

  1. Lines 1857-1865. The DP/multi-node branch runs only with a config, no external launcher, no elastic EP, and DP > 1 or several nodes. A dense model's engine reset its DP size to 1, so it never enters for DP.
  2. Lines 1869-1871. Shift the rank by dp_rank × world_size and widen the world to all DP ranks.

Then the default process group starts, with a gloo fallback when the backend is not available ({{cite vllm/distributed/parallel_state.py:1927-1982}}), and the world GroupCoordinator is made once. When one DP replica spans several nodes and DP > 1, an extra inner_dp_world group with a broadcaster is made for the executor's cross-node queue; with DP = 1 the name points to the world group ({{cite vllm/distributed/parallel_state.py:2022-2038}}).

initialize_model_parallel

Every group comes from this one tensor: TP with view(-1, TP), PP with transpose(2, 4), DP with transpose(1, 4), PCP with transpose(3, 4), and EP (MoE only) with transpose(1, 2) into rows of DP × PCP × TP ({{cite vllm/distributed/parallel_state.py:2256-2345}}). With elastic EP, TP/PP/PCP use a local grid and DP/EP/EPLB become stateless groups ({{cite vllm/distributed/parallel_state.py:2122-2140}}, {{cite vllm/distributed/parallel_state.py:2297-2305}}). The function ends with one INFO log line per rank, logged once ({{cite vllm/distributed/parallel_state.py:2372-2385}}).

Tear-down

destroy_model_parallel destroys the groups in the order ETP, TP, Engram DP, DCP, PCP, PP, DP, EP, EPLB ({{cite vllm/distributed/parallel_state.py:2480-2525}}). Each GroupCoordinator.destroy first destroys its device communicator, because communicator workspaces may need the groups for their own tear-down ({{cite vllm/distributed/parallel_state.py:1400-1413}}).

vllm serve meta-llama/Llama-3.1-8B-Instruct -tp 2, worker rank 1 (derived from the code above):

  1. init_distributed_environment(world_size=2, rank=1, "file:///tmp/vllm_dist_…", local_rank=1, "nccl"): no DP branch; default PG of 2 ranks; _WORLD = ranks [0, 1], no device communicator; _NODE_COUNT = 1.
  2. all_ranks = arange(2).reshape(1, 1, 1, 1, 2).
  3. _TP = [0, 1] (tp:0), with a CudaCommunicator and a 6 × 4 MiB MessageQueue. _ETP is the same object.
  4. _DCP, _PCP, _PP, _DP: two groups of one rank each ([0] and [1]), so this rank's object has no communicator and no broadcaster.
  5. _EP, _EPLB: None, because Llama is not an MoE model.
  6. The log: "rank 1 in world size 2 is assigned as DP rank 0, PP rank 0, PCP rank 0, TP rank 1, ETP rank 1, EP rank N/A, EPLB rank N/A".

Every new_group call above makes two PyTorch groups (NCCL and gloo), and each rank takes part in both rows of each size-1 group kind. That is 2 + 2 + 4 × 4 = 20 new_group calls for this worker: world and TP have 1 row each, DCP, PCP, PP and DP have 2 rows each, and each row needs two calls. The communicators then do their own setup (derived from lines 501-518 and the group list).

What does GroupCoordinator.all_reduce do in a group of one rank?

It returns the input tensor; no kernel runs ({{cite vllm/distributed/parallel_state.py:739-741}}).

 Why must every rank call torch.distributed.new_group for every row, even rows it does not belong to?

new_group is a collective call in PyTorch. The constructor loops over all rows of group_ranks and keeps only its own pair ({{cite vllm/distributed/parallel_state.py:501-518}}).

 A PP stage sends a hidden_states tensor of [2048, 4096] BF16 with TP = 4. How many bytes does each TP rank send for it, and how does the receiver get the full tensor?

The size divides by 4, so each rank sends its 1/4 slice: 2048 × 4096 × 2 / 4 = 4 MiB ({{cite vllm/distributed/parallel_state.py:1068-1080}}, {{cite vllm/distributed/parallel_state.py:1219-1222}}). The receiver posts an irecv into its slice and runs an all-gather on the TP group in a post-processing callback ({{cite vllm/distributed/parallel_state.py:1332-1355}}).

 In the TP = 2 example of the deep dive, which groups of worker 1 have a device communicator, and why does the PP group have none?

Only the TP group (and ETP, the same object). The PP, DP, PCP and DCP groups of this rank have one rank each, and the constructor makes a communicator only when world_size > 1 ({{cite vllm/distributed/parallel_state.py:549}}). The world group is built with use_device_communicator=False ({{cite vllm/distributed/parallel_state.py:1507-1516}}).
