It is the reference model file of vLLM; nine registry names and many other model files reuse it. ---

Purpose

vllm/model_executor/models/llama.py implements the Llama architecture with vLLM layers, so that the worker can build it, load a Hugging Face checkpoint into it, and run it in the forward pass of each step.

Filevllm/model_executor/models/llama.py, 585 lines of Python. The header says it is adapted from the Transformers Llama code, v4.28.0 ({{cite vllm/model_executor/models/llama.py:4-5}}).

Where it sits

Who calls it

  • The registry. Nine names map to this file, seven of them to LlamaForCausalLM: LlamaForCausalLM, LLaMAForCausalLM, InternLM3ForCausalLM, IQuestCoderForCausalLM, TeleChat3ForCausalLM, and the embedding names LlamaModel and MistralModel ({{cite vllm/model_executor/models/registry.py:140-155}}, {{cite vllm/model_executor/models/registry.py:212}}, {{cite vllm/model_executor/models/registry.py:231-238}}). Two more map to the bidirectional wrappers ({{cite vllm/model_executor/models/registry.py:230}}, {{cite vllm/model_executor/models/registry.py:326-329}}). (Counts from an evaluation of the tables.)
  • The loader. initialize_model() builds the class; the default loader calls load_weights() ({{cite vllm/model_executor/model_loader/default_loader.py:503}}).
  • The model runner. Each step calls the model with input_ids, positions, inputs_embeds and intermediate_tensors ({{cite vllm/v1/worker/gpu/model_runner.py:1984-2009}}), then compute_logits() on the sampled rows.
  • Other model files. For example MistralForCausalLM, Phi3ForCausalLM and TeleChat2ForCausalLM subclass LlamaForCausalLM ({{cite vllm/model_executor/models/mistral.py:236}}, {{cite vllm/model_executor/models/phi3.py:10}}, {{cite vllm/model_executor/models/telechat2.py:107}}).

What it calls

  • QKVParallelLinear, MergedColumnParallelLinear, RowParallelLinear ({{cite vllm/model_executor/models/llama.py:45-49}}), VocabParallelEmbedding and ParallelLMHead ({{cite vllm/model_executor/models/llama.py:53-56}}).
  • Attention or EncoderOnlyAttention ({{cite vllm/model_executor/models/llama.py:39-42}}).
  • CustomOps: RMSNorm, SiluAndMul, and the rotary embedding from get_rope ({{cite vllm/model_executor/models/llama.py:38}}, {{cite vllm/model_executor/models/llama.py:44}}, {{cite vllm/model_executor/models/llama.py:52}}).
  • maybe_fused_act_quant, which can fuse the activation with the quantization of the next layer's input ({{cite vllm/model_executor/models/llama.py:43}}, {{cite vllm/model_executor/models/llama.py:120}}).
  • Helpers from models/utils.py and mixins from models/interfaces.py ({{cite vllm/model_executor/models/llama.py:61-79}}).

Walk through the main methods

LlamaAttention.__init__: sliding windows and the attention class

The head arithmetic and the two linear layers are on {{link concepts/model-definition}} (lines 143-181). The second half of the constructor:

  1. Line 183. _init_rotary_emb calls get_rope with the head size, max_position_embeddings and the config's rope_parameters, NeoX style (lines 236-248).
  2. Lines 186-204. If the config has layer_types, a layer marked sliding_attention gets config.sliding_window. The layer index comes from the prefix (line 141). For an EAGLE-3 draft, the index is shifted by target_layer_count.
  3. Lines 206-210. ENCODER_ONLY selects EncoderOnlyAttention; everything else uses Attention.
  4. Lines 212-222. The attention layer gets per-rank heads (self.num_heads, self.num_kv_heads), the scale head_dim ** -0.5 (line 162) and its prefix.

LlamaDecoderLayer: config knobs and the residual

  1. Line 263. The quant config comes from get_quant_config(), which subclasses can override (lines 332-334).
  2. Lines 268-274. attention_bias or bias turns on biases in QKV and o_proj; qkv_bias sets the QKV bias alone. The comments name the models that need this.
  3. Lines 280-283. is_causal=False in the config makes the layer bidirectional, for embedding models.
  1. Lines 320-322. The first layer has no residual yet: it keeps the input as the residual and normalizes.
  2. Line 324. Later layers call the norm with the residual. RMSNorm adds it and normalizes in one op, and returns the new residual too.
  3. Line 328. The same fused add-and-norm before the MLP. The layer returns (hidden_states, residual); the final norm of LlamaModel adds the last residual (line 452).

LlamaModel.load_weights and LlamaForCausalLM.load_weights: the load path

Follow one tensor, model.layers.0.mlp.up_proj.weight, in a TP = 2 worker:

  1. The default loader calls LlamaForCausalLM.load_weights(iterator) ({{cite vllm/model_executor/model_loader/default_loader.py:503}}).
  2. The outer AutoWeightsLoader has no model mapper. It adds the quant config mappers, if any, and the rule that drops old rotary tables ({{cite vllm/model_executor/models/utils.py:460-473}}).
  3. The walk groups by model and finds self.model, a LlamaModel with its own load_weights. It passes the rest of the name: layers.0.mlp.up_proj.weight ({{cite vllm/model_executor/models/utils.py:387-400}}).
  4. LlamaModel.load_weights makes a second AutoWeightsLoader with hf_to_vllm_mapper. .up_proj becomes .gate_up_proj with shard id 1 ({{cite vllm/model_executor/models/llama.py:354-355}}).
  5. The walk goes layers → 0 → mlp → gate_up_proj. MergedColumnParallelLinear has a load_weights; it reads shard_id = 1 from the tensor and calls the parameter's loader ({{cite vllm/model_executor/layers/linear.py:985-1000}}).
  6. The v2 loader computes offset 14336 / 2 = 7168 and size 7168 in the parameter. It copies checkpoint rows rank × 7168 to rank × 7168 + 7167 ({{cite vllm/model_executor/layers/linear.py:965-983}}, {{cite vllm/model_executor/parameter.py:153-173}}).
  7. The loaded name goes back up the tree with its prefixes: model.layers.0.mlp.gate_up_proj.weight. The default loader uses the set of these names for its completeness check ({{cite vllm/model_executor/model_loader/default_loader.py:510-523}}).

The tensor lm_head.weight takes another path. In the outer walk, lm_head is a ParallelLMHead without load_weights, so its weight parameter uses VocabParallelEmbedding.weight_loader ({{cite vllm/model_executor/models/utils.py:416-424}}). If tie_word_embeddings is set, lm_head.weight is the same object as model.embed_tokens.weight (lines 509-510), and the loader skips the second name ({{cite vllm/model_executor/models/utils.py:255-259}}). One exception: if the config says tied but the checkpoint has its own lm_head, VllmConfig turns the flag off, so the head loads ({{cite vllm/config/vllm.py:1594-1599}}). After loading, vLLM ties the two again if they are equal ({{cite vllm/config/model.py:1255-1281}}, {{cite vllm/model_executor/model_loader/utils.py:155}}).

LlamaForCausalLM: class attributes

  1. Lines 464-472. The mixins; {{link concepts/model-definition}} has a table of what each one adds.
  2. Line 473. The outer class shares the mapper of LlamaModel. SupportsQuant.__new__ gives its rename-only part to the quant config, so names in ignored_layers can match vLLM names ({{cite vllm/model_executor/models/interfaces.py:1292-1299}}). For Llama this part is empty: get_rename_mapper() drops the stacked rules, which are the only rules of this mapper ({{cite vllm/model_executor/models/utils.py:180-199}}).
  3. Lines 475-478. packed_modules_mapping tells LoRA and the quant config which checkpoint layers form each stacked layer.
  4. Lines 479-482. embedding_modules lists the layers that get LoRA embedding buffers; Mistral clears it ({{cite vllm/model_executor/models/mistral.py:237-238}}).

Which class of llama.py carries @support_torch_compile?

LlamaModel ({{cite vllm/model_executor/models/llama.py:337-347}}). LlamaForCausalLM.forward only calls it.

 Why does LlamaForCausalLM.load_weights pass no mapper, although the class has hf_to_vllm_mapper?

The outer loader hands every model.* tensor to LlamaModel.load_weights, which applies the mapper itself ({{cite vllm/model_executor/models/utils.py:387-400}}, {{cite vllm/model_executor/models/llama.py:459-461}}). The class attribute on the outer class is for others: SupportsQuant gives its rename part to the quant config ({{cite vllm/model_executor/models/interfaces.py:1296-1297}}). For Llama that part is empty, because the mapper has only stacked rules ({{cite vllm/model_executor/models/utils.py:186-196}}).

 A config has "qkv_bias": true and no attention_bias. Which layers get a bias?

Only qkv_proj. bias_o_proj takes the value of attention_bias before qkv_bias overrides attention_bias ({{cite vllm/model_executor/models/llama.py:268-274}}).

 Follow model.layers.0.mlp.gate_proj.weight on TP rank 1 of a Llama-3-8B with TP = 2. Which rows of the checkpoint tensor end up where?

The mapper renames it to layers.0.mlp.gate_up_proj.weight with shard id 0 ({{cite vllm/model_executor/models/llama.py:354}}). The v2 loader uses offset 0 and size 14336 / 2 = 7168 in the parameter ({{cite vllm/model_executor/layers/linear.py:967-970}}). The parameter copies checkpoint rows 7168-14335 (rank 1 × 7168) into its rows 0-7167 ({{cite vllm/model_executor/parameter.py:168-173}}).
