Purpose

These two files define what an attention backend must provide (backend.py) and how a layer gets one (selector.py).

Where it sits

Who calls it

  • Selector. Attention.__init__ calls get_attn_backend ({{cite vllm/model_executor/layers/attention/attention.py:349-360}}). The MLA layer does the same with use_mla=True.
  • Builders. AttentionGroup.create_metadata_builders instantiates them ({{cite vllm/v1/worker/utils.py:330-339}}); build_attn_metadata calls build ({{cite vllm/v1/worker/gpu/attn_utils.py:574-576}}).
  • Impls. The unified ops call impl.forward and impl.do_kv_cache_update ({{link code/model-executor-layers-attention-attention}}).
  • Platforms. CUDA calls validate_configuration on each candidate ({{cite vllm/platforms/cuda.py:389-417}}).

What it calls

  • current_platform.get_attn_backend_cls and resolve_obj_by_qualname (selector, {{cite vllm/v1/attention/selector.py:218-228}}).
  • get_kv_quant_mode for the impl's KV quantization mode ({{cite vllm/v1/attention/backend.py:895-898}}).
  • ops.concat_and_cache_mla in the MLA cache write ({{cite vllm/v1/attention/backend.py:1118-1128}}).

Walk through the main methods

AttentionBackend.validate_configuration

Each failed check adds a human-readable reason; an empty list means "valid". The rest of the method checks sliding window, R-SWA, non-causal attention, batch invariance, the KV connector, PCP, DCP and adaptive verification, then the backend's own supports_combination ({{cite vllm/v1/attention/backend.py:332-369}}). The page {{link concepts/attention-backend-selection}} shows how CUDA uses the reasons.

AttentionMetadataBuilder.__init__ and build

  1. Line 595. CUDA graph support defaults to NEVER; read it through get_cudagraph_support() (line 594).
  2. Line 599. reorder_batch_threshold: the query length up to which the builder treats a request as a decode.
  3. Lines 602, 604, 610. Feature flags: block-table update, block-table width, capture-safe draft updates.
  4. Lines 613-624. The constructor gets the KV cache spec, the layer names of the group, the config and the device.

build(common_prefix_len, common_attn_metadata, fast_build=False) is abstract ({{cite vllm/v1/attention/backend.py:686-704}}). build_for_cudagraph_capture and build_for_drafting call it by default (lines 720-751).

AttentionImpl.forward

The constructor takes the same ten arguments that Attention.__init__ passes. forward gets the layer (for its scales), the tensors, the KV cache view, the metadata and the output buffer. The fused hooks (do_rope_and_kv_cache_update and others, lines 973-1031) are used only by Inductor fusion passes when the impl says it supports them.

get_attn_backend (selector.py)

  1. Lines 158-180. The selector config mixes the layer's facts with run-wide facts: KV connector, PCP, DCP, batch invariance, adaptive verification and R-SWA.
  2. Lines 184-192. A per-kind override wins over the global backend.
  3. Lines 196-203. The cached call. The run-wide KV cache dtype is part of the cache key.

The block size goes into the config only when the user set --block-size ({{cite vllm/v1/attention/selector.py:134-138}}). _cached_get_attn_backend is decorated with @cache, so each set of facts asks the platform once per process ({{cite vllm/v1/attention/selector.py:206-228}}).

Deep dive

The sections below give the full detail. Open them one at a time, or use Open all deep dives at the top of the page.

  • naive_query_lens(): query_start_loc[1:] - query_start_loc[:-1], "naive" because it assumes that one query ends where the next starts ({{cite vllm/v1/attention/backend.py:482-484}}).
  • compute_num_computed_tokens(): seq_lens - query_lens on the device, cached ({{cite vllm/v1/attention/backend.py:489-494}}).
  • token_to_req_indices(buffer): the request index of each token, built from the device query_start_loc, cached ({{cite vllm/v1/attention/backend.py:496-518}}).
  • unpadded(num_actual_tokens, num_actual_reqs): slice every field back to the real sizes, marked "remove once we have FULL-CG spec-decode support" ({{cite vllm/v1/attention/backend.py:520-554}}).

Every impl gets its DCP and PCP rank and world size in __new__, so subclasses need not call a base constructor ({{cite vllm/v1/attention/backend.py:853-878}}). need_to_return_lse_for_decode is true only with DCP > 1 and an impl that can return the softmax LSE. The comment on lse_base_on_e warns that a wrong base "silently corrupts the cross-shard softmax denominator" ({{cite vllm/v1/attention/backend.py:808-818}}).
  1. A subclass of AttentionBackend with get_name, get_impl_cls and get_builder_cls ({{cite vllm/v1/attention/backend.py:81-94}}), plus the supports_* answers that differ from the defaults.
  2. A metadata dataclass and a builder with __init__ and build; set _cudagraph_support if graphs are safe.
  3. An impl with __init__ and forward; if forward_includes_kv_cache_update = False, also do_kv_cache_update.
  4. Registration through register_backend and selection by the platform or --attention-backend ({{link concepts/attention-backend-selection}}).

Which three static methods must every backend implement?

get_name, get_impl_cls and get_builder_cls ({{cite vllm/v1/attention/backend.py:81-94}}).

 Why does the selector pass _run_kv_cache_dtype to the cached function although the platform can read the config?

So the cache key changes when the run-wide KV cache dtype changes. The comment says some platform selectors inspect it ({{cite vllm/v1/attention/selector.py:214-215}}).

 What does max_decode_query_len return with 4 speculative tokens on Model Runner V2, and who uses it?

5 (1 + 4); the extra term for parallel drafting applies only to Model Runner V1 ({{cite vllm/v1/attention/backend.py:584-589}}). Builders that run spec decoding as decodes raise their reorder_batch_threshold to it ({{cite vllm/v1/attention/backend.py:666-678}}).
