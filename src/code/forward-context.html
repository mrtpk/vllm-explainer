Purpose

vllm/forward_context.py holds one global object during each forward pass, so that layers and CUDA graph wrappers can read per-step data without function arguments.

Where it sits

Who calls it

  • GPUModelRunner.execute_model, around the model call in PIECEWISE and eager mode (FULL mode replays a graph without a context) ({{cite vllm/v1/worker/gpu/model_runner.py:2024-2053}}).
  • ModelCudaGraphManager.capture, around each capture run ({{cite vllm/v1/worker/gpu/cudagraph_utils.py:754-771}}).
  • Any code inside the forward pass that needs step data: get_forward_context().

What it calls

  • coordinate_batch_across_dp when an MoE model with DP > 1 has no token counts yet ({{cite vllm/forward_context.py:311-322}}).
  • The platform hook set_additional_forward_context ({{cite vllm/forward_context.py:334-343}}).
  • current_platform.synchronize, only when batch-size logging is on ({{cite vllm/forward_context.py:368-370}}).

Example: a batch of 300 tokens runs as PIECEWISE with 304 padded tokens. The descriptor is BatchDescriptor(num_tokens=304, has_lora=False, num_active_loras=0), which is also the key that each piece wrapper captured at start-up (derived from {{link concepts/compile-and-cuda-graphs}}).

The descriptor has five fields ({{cite vllm/forward_context.py:36-56}}). Model Runner V2 sets only num_tokens, has_lora and num_active_loras; num_reqs stays None and uniform stays False, because PIECEWISE graphs do not depend on them. The FULL graph choice uses a separate class, BatchExecutionDescriptor, in gpu/cudagraph_utils.py ({{cite vllm/v1/worker/gpu/cudagraph_utils.py:70-85}}).

_forward_context is one module-level variable ({{cite vllm/forward_context.py:205}}). Each worker process has its own copy. Inside a process, the model runs in one thread at a time. Dual-batch overlap uses threads that hand off one compute stream ({{cite vllm/v1/worker/gpu/attn_utils.py:301-303}}); it passes the list form of attn_metadata and slot_mapping, one dict per micro-batch ({{cite vllm/forward_context.py:146-150}}).

Which function do layers call to read the current step data?

get_forward_context(), which returns the module-level _forward_context ({{cite vllm/forward_context.py:208-214}}).

 Is no_compile_layers a copy of static_forward_context?

No. The field comment says "copy", but create_forward_context passes the dict object itself ({{cite vllm/forward_context.py:142-143}}, {{cite vllm/forward_context.py:248}}).

 Why can VLLM_LOG_BATCHSIZE_INTERVAL=0 make a server slower, and when is the setting read?

When it is 0 or more, every forward pass inside set_forward_context with attention metadata ends with current_platform.synchronize() ({{cite vllm/forward_context.py:295}}, {{cite vllm/forward_context.py:363-370}}), which removes the CPU/GPU overlap. In Model Runner V2 these are the eager and PIECEWISE steps. The module reads the variable once, at import ({{cite vllm/forward_context.py:22-25}}).
