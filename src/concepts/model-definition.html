--- title: How a vLLM model file is written (llama.py) nav_title: Model definition level: Advanced prerequisites: concepts/oot-models, learn/pytorch-for-serving, learn/tp-pp-in-practice related: concepts/weight-loading, concepts/tp-layers, code/model-executor-models-llama, concepts/model-interfaces, concepts/custom-ops, concepts/forward-context, concepts/compile-and-cuda-graphs, code/model-executor-layers-linear summary: A vLLM model file rebuilds the Hugging Face architecture from vLLM layers. Every constructor takes vllm_config and a prefix, linear layers are tensor-parallel, attention is an Attention layer object, and pipeline stages use PPMissingLayer and IntermediateTensors. llama.py is the example. --- A vLLM model file builds the network from tensor-parallel layers, names every layer with a prefix, and leaves attention, compilation and weight loading to vLLM.

The idea

A decoder model is a stack of layers: an embedding, N decoder layers and an LM head. Each decoder layer has a norm, attention, a norm and an MLP ({{deepinfer learn/transformer | Inside a transformer}}). vLLM does not run the Transformers class of the checkpoint. It runs its own class for the architecture name, for example LlamaForCausalLM in vllm/model_executor/models/llama.py ({{link concepts/oot-models}}).

The vLLM class has the same math and the same parameter tree as the Transformers class. It differs in four ways:

  • Constructor contract. Every class takes vllm_config (the whole {{term vllm-config}}) and a {{term model-prefix}}, the dotted name of the layer in the tree.
  • Tensor-parallel layers. Linear layers and the embedding are vLLM classes that hold only the slice of this {{term tensor-parallel}} rank, and do the communication themselves ({{link concepts/tp-layers}}).
  • An attention layer object. The model gives Q, K and V to an Attention layer. That layer finds its KV cache and the metadata of the step itself, through the {{term forward-context}} ({{link concepts/forward-context}}).
  • Pipeline stages. Layers that another {{term pipeline-parallel}} stage owns are placeholders, and a stage that is not the last returns {{term intermediate-tensors}} instead of hidden states.

Other work is not in the model file. A decorator adds torch.compile; the compile backend and the model runner add CUDA graphs. A loader streams the weights in, and each parameter cuts its own slice ({{link concepts/weight-loading}}). Mixin classes tell the registry what the model supports ({{link concepts/model-interfaces}}).

An everyday comparison. Think of a new office building. The builders put a room number on every door, such as "3.12.B" (floor, corridor, room). Later, the furniture company, the phone list and the cleaning plan all use these numbers. A door with a wrong number gets the wrong desk or no phone. The comparison stops here. In vLLM, nobody checks the number on the door. Two systems read the number, and two systems walk the real module tree. When the number and the path are different, the systems disagree.

The picture

Read the tree from the top. Each parent passes a longer prefix to its children, so the prefix of a row is the dotted path to it. Blue and violet rows are the tensor-parallel linear layers. The amber row is the attention layer that registers itself under its prefix.

In the code

Step 1: the constructor contract

The worker builds the model in initialize_model(). It checks by name that the constructor has the parameters vllm_config and prefix. Then it calls the class with both, inside set_current_vllm_config ({{cite vllm/model_executor/model_loader/utils.py:96-103}}). A class without them gets a DeprecationWarning and an argument guess; {{link concepts/oot-models}} explains that path. The root gets prefix="": Model Runner V2 calls load_model() without a prefix, so the default "" goes to create_model() ({{cite vllm/v1/worker/gpu/model_runner.py:403-406}}, {{cite vllm/model_executor/model_loader/base_loader.py:63-80}}).

  1. Lines 487-488. Keyword-only vllm_config and prefix. The registry also checks the keyword vllm_config when it inspects the class ({{link concepts/model-interfaces}}).
  2. Lines 492-493. The model reads what it needs from vllm_config: the Hugging Face config and the quantization config. Inner classes do the same.
  3. Lines 496-500. The inner model gets the prefix maybe_prefix(prefix, "model"), which is "model" for the root ({{cite vllm/model_executor/models/utils.py:971-982}}).
  4. Lines 502-508. Only the last pipeline stage builds the LM head.
  5. Lines 519-521. The model exposes a factory for empty intermediate tensors; pipeline parallelism needs it.

Step 2: how each layer gets its prefix, and why it matters

Each constructor adds the attribute name to the prefix it got. The decoder layer gives f"{prefix}.self_attn" and f"{prefix}.mlp" ({{cite vllm/model_executor/models/llama.py:285-307}}). The attention class gives .qkv_proj, .o_proj and .attn ({{cite vllm/model_executor/models/llama.py:165-181}}, {{cite vllm/model_executor/models/llama.py:212-222}}). make_layers() builds the list of decoder layers with prefix=f"{prefix}.{idx}" ({{cite vllm/model_executor/models/utils.py:911-917}}). So the QKV layer of layer 0 gets the prefix model.layers.0.self_attn.qkv_proj.

No code checks that the prefix equals the attribute path of the layer. But the quantization config compares the prefix with checkpoint names, and the weight loader and LoRA use the module tree. So use the attribute path as the prefix; then all four parts use the same name (derived from the four rows above). The section What can go wrong gives the failures.

Step 3: tensor-parallel layers

LlamaAttention divides the heads by the TP size and builds a QKVParallelLinear and a RowParallelLinear:

  1. Lines 145-146. The query heads must divide by the TP size. Start-up checks this earlier, with a clear error ({{cite vllm/config/model.py:1557-1564}}).
  2. Lines 148-156. KV heads are split when there are enough of them, and replicated when TP is larger ({{link learn/tp-pp-in-practice}} has the table).
  3. Lines 160-161. q_size and kv_size are per rank. The forward pass splits the QKV output with them.
  4. Lines 165-181. The model gives the total head counts to QKVParallelLinear and the full input size to o_proj. The layers divide by the TP size themselves.

LlamaMLP uses a MergedColumnParallelLinear for gate and up, and a RowParallelLinear for down ({{cite vllm/model_executor/models/llama.py:95-111}}); {{link learn/tp-pp-in-practice}} shows the shapes. The embedding is a VocabParallelEmbedding and the head is a ParallelLMHead ({{cite vllm/model_executor/models/llama.py:382-386}}, {{cite vllm/model_executor/models/llama.py:503-508}}). The model code calls no collective itself. The page {{link concepts/tp-layers}} explains each layer class.

Step 4: the attention layer and the CustomOps

  1. Lines 212-222. Attention gets the per-rank head counts, the scale, the cache and quantization configs, an optional sliding window, and its prefix. When it is built, it selects an {{term attention-backend}}, unless the caller gives one ({{cite vllm/model_executor/layers/attention/attention.py:349-350}}). It also registers itself in the forward context.
  2. Line 229. One GEMM computes Q, K and V for the heads of this rank: [T, q_size + 2 × kv_size].
  3. Lines 230-231. The split, then RoPE on Q and K.
  4. Line 232. self.attn(q, k, v) passes no KV cache and no metadata. The attention op uses the layer name to find the metadata and the layer object (with its KV cache) in the forward context ({{cite vllm/model_executor/layers/attention/attention.py:705-717}}). The page {{link concepts/forward-context}} explains how.
  5. Line 233. The row-parallel o_proj adds the partial sums of the ranks.

Three small layers are {{term custom-op | CustomOps}}: RMSNorm ({{cite vllm/model_executor/layers/layernorm.py:38-39}}), the rotary embedding from get_rope() ({{cite vllm/model_executor/layers/rotary_embedding/base.py:14-15}}) and SiluAndMul ({{cite vllm/model_executor/layers/activation.py:115-116}}). Each one picks its forward method when it is built ({{link concepts/custom-ops}}). get_rope() keeps a cache keyed by its arguments, so all 32 layers share one rotary object ({{cite vllm/model_executor/layers/rotary_embedding/__init__.py:84-85}}, {{cite vllm/model_executor/layers/rotary_embedding/__init__.py:351}}).

Step 5: LlamaModel, compilation and pipeline stages

The decorator wraps LlamaModel.forward for torch.compile and CUDA graphs ({{link concepts/compile-and-cuda-graphs}}). It sits on LlamaModel, not on LlamaForCausalLM, so compute_logits stays outside the compiled graph.

The constructor builds the parts of this pipeline stage only:

  1. Lines 377-388. The embedding is real on the first stage. It is also real on the last stage when the head shares its weight, or when a speculative drafter needs it. Elsewhere it is a {{term pp-missing-layer}}.
  2. Lines 389-393. make_layers() builds real layers only for indices start_layer to end_layer - 1. All other slots are PPMissingLayer, so the indices and names stay the same on every stage ({{cite vllm/model_executor/models/utils.py:886-919}}).
  3. Lines 394-397. The final norm exists on the last stage only.
  4. Lines 399-401. Empty intermediate tensors have the keys hidden_states and residual, each [batch_size, hidden_size] of zeros ({{cite vllm/model_executor/models/utils.py:955-968}}).
  1. Lines 414-423. The first stage starts from the token embeddings, or from inputs_embeds when the runner gives them. Other stages read hidden_states and residual from the stage before.
  2. Lines 432-438. The loop runs only the layers of this stage. Each layer returns the new hidden states and the residual.
  3. Lines 443-450. A stage that is not the last returns IntermediateTensors.
  4. Line 452. The last stage applies the final norm. It returns hidden states of shape [T, hidden_size], not logits.

The decoder layer keeps the residual outside the norm. input_layernorm(hidden_states, residual) adds the residual and normalizes in one call, and returns both tensors ({{cite vllm/model_executor/models/llama.py:320-328}}, {{cite vllm/model_executor/layers/layernorm.py:85-99}}).

Step 6: LlamaForCausalLM: forward, logits and mixins

  1. Lines 541-543. forward(input_ids, positions, intermediate_tensors, inputs_embeds) only calls the inner model. The model runner builds these four arguments ({{cite vllm/v1/worker/gpu/model_runner.py:1984-2009}}).
  2. Line 550. compute_logits applies the head through LogitsProcessor. To sample, the runner calls it only on the rows that sample a token, hidden_states[logits_indices] ({{cite vllm/v1/worker/gpu/model_runner.py:1637-1638}}). Prompt logprobs call it on prompt rows too ({{cite vllm/v1/worker/gpu/model_runner.py:2177-2178}}).
  3. Line 557. compute_logits_local skips the gather. The runner uses it for batch-sharded sampling.
  4. Lines 560-561. load_weights hands the checkpoint stream to AutoWeightsLoader ({{link concepts/weight-loading}}).

Step 7: how other files reuse llama.py

Nine registry names point to llama.py. Seven of them use LlamaForCausalLM directly, for example InternLM3ForCausalLM and TeleChat3ForCausalLM ({{cite vllm/model_executor/models/registry.py:140-155}}, {{cite vllm/model_executor/models/registry.py:212}}). The embedding table also copies every name that maps to LlamaForCausalLM ({{cite vllm/model_executor/models/registry.py:231-238}}). (Counts from an evaluation of the tables at this commit.)

Other model files subclass the Llama classes. MistralForCausalLM subclasses LlamaForCausalLM ({{cite vllm/model_executor/models/mistral.py:236}}), and so does Phi3ForCausalLM ({{cite vllm/model_executor/models/phi3.py:10}}). TeleChat2ForCausalLM adds its own name mapper and builds TeleChat2Model, a subclass of LlamaModel ({{cite vllm/model_executor/models/telechat2.py:107-127}}, {{cite vllm/model_executor/models/telechat2.py:35}}). 21 files in vllm/ import from llama.py (git grep at this commit). The file has two hooks for this reuse:

  • A layer_type argument, so a subclass can give its own decoder layer class ({{cite vllm/model_executor/models/llama.py:360-366}}, {{cite vllm/model_executor/models/llama.py:523-529}}).
  • LlamaDecoderLayer.get_quant_config(), which the docstring says to override in subclasses ({{cite vllm/model_executor/models/llama.py:332-334}}).

A second model tree: vllm/models/

Some new model families do not live in vllm/model_executor/models/. They have one package per family in vllm/models/, with sub-packages per hardware vendor. The package __init__.py imports the implementation for current_platform, for example the NVIDIA, AMD, XPU or CPU variant of DeepSeek V4 ({{cite vllm/models/deepseek_v4/__init__.py:1-48}}). For the registry they are normal lazy entries ({{link concepts/oot-models}}). This site does not explain these packages further; llama.py is the one model example.

Each decoder layer does two all-reduces of [2048, 4096] BF16 values: one in o_proj and one in down_proj. The embedding adds one more all-reduce per step ({{cite vllm/model_executor/layers/vocab_parallel_embedding.py:558-563}}). So a step has 2 × 32 + 1 = 65 all-reduces of 16 MiB each (derived). The logits add one all-gather of [16, 64128] per rank. Batch-sharded sampling, which is off by default, changes this last step ({{cite vllm/config/parallel.py:192-198}}).

The table ignores CUDA graph padding of T and the fused all-reduce paths. The attention output size uses num_heads × head_size_v, which equals 2,048 here ({{cite vllm/model_executor/layers/attention/attention.py:525-529}}).

So a name in a quantization config, such as model.embed_tokens, cannot match it: an exact or suffix compare with "" fails ({{cite vllm/model_executor/layers/quantization/utils/quant_utils.py:624-637}}). compressed-tensors can still match it by its class name, for example with the target Embedding ({{cite vllm/model_executor/layers/quantization/compressed_tensors/utils.py:105-109}}, {{cite vllm/model_executor/layers/quantization/utils/config_utils.py:444-445}}). (Derived.)

extract_layer_index() finds the one integer in a prefix: model.layers.0.self_attn gives 0. A prefix with two integers fails its assertion, unless the caller says that a layer has several attention modules ({{cite vllm/model_executor/models/utils.py:1010-1042}}).

Take 32 layers and PP = 2. get_pp_indices() gives stage 0 the layers 0-15 and stage 1 the layers 16-31 ({{link learn/tp-pp-in-practice}} explains the split rule).

  1. Build, stage 0. embed_tokens is real. layers[0:16] are real; layers[16:32] are PPMissingLayer. norm and lm_head are PPMissingLayer, and there is no logits_processor ({{cite vllm/model_executor/models/llama.py:502-517}}).
  2. Build, stage 1. embed_tokens is PPMissingLayer unless the head shares its weight or a speculative drafter needs it. layers[0:16] are placeholders; norm, lm_head and logits_processor are real.
  3. Forward, stage 0. Embed, run layers 0-15, return IntermediateTensors({"hidden_states", "residual"}), each [T, 4096].
  4. Forward, stage 1. The runner fills its own buffers from the received tensors and passes them as intermediate_tensors ({{cite vllm/v1/worker/gpu/model_runner.py:1993-2009}}). The model reads them (llama.py lines 421-423), runs layers 16-31, then the final norm.
  5. Weights. AutoWeightsLoader skips every PPMissingLayer, so the checkpoint tensors of other stages are read but not stored ({{cite vllm/model_executor/models/utils.py:382-383}}). Hand-written loaders call is_pp_missing_parameter() instead ({{cite vllm/model_executor/models/utils.py:944-952}}).

PPMissingLayer is a torch.nn.Identity whose forward returns its first argument ({{cite vllm/model_executor/models/utils.py:852-860}}). IntermediateTensors is a thin wrapper around a dict of tensors, with indexing by key or by slice ({{cite vllm/sequence.py:12-34}}). With EAGLE-3 and PP, the dict also carries keys aux_hidden_states_<i> ({{cite vllm/model_executor/models/interfaces.py:1652-1661}}).
  1. Constructors take vllm_config and prefix; children get f"{prefix}.{attr}" or maybe_prefix(prefix, attr).
  2. Linear layers are QKVParallelLinear, MergedColumnParallelLinear, RowParallelLinear or ReplicatedLinear, each with quant_config and prefix.
  3. Attention is an Attention layer with the per-rank head counts and a unique prefix.
  4. The inner model has embed_input_ids and forward(input_ids, positions, intermediate_tensors, inputs_embeds); the outer class has compute_logits. The registry checks these names ({{link concepts/model-interfaces}}).
  5. For PP: build layers with make_layers, use PPMissingLayer, return IntermediateTensors, set make_empty_intermediate_tensors, and inherit SupportsPP.
  6. For loading: a load_weights with AutoWeightsLoader and a WeightsMapper for stacked parameters ({{link concepts/weight-loading}}).
  7. For LoRA: packed_modules_mapping that lists the parts of each stacked layer.

What can go wrong

  • Two attention layers with the same prefix. The second one raises ValueError: Duplicate layer name while the model is built ({{cite vllm/model_executor/layers/attention/attention.py:443-444}}). A model that builds its layers in a loop must put the index in the prefix.
  • A prefix that is not the real path. No error occurs at once. The quantization config compares the wrong name with its lists, so a layer can get the wrong method. For example, it can get FP8 although the checkpoint lists it in ignored_layers ({{cite vllm/model_executor/layers/quantization/fp8.py:180-190}}). An attention prefix without exactly one layer number fails the assertion of extract_layer_index() ({{cite vllm/model_executor/models/llama.py:141}}, {{cite vllm/model_executor/models/utils.py:1027-1030}}).
  • Heads that do not divide. 32 query heads with TP = 3 stop start-up with "must be divisible by tensor parallel size" ({{cite vllm/config/model.py:1559-1564}}).
  • Another activation. LlamaMLP accepts only silu and raises ValueError for other values of hidden_act ({{cite vllm/model_executor/models/llama.py:112-115}}).
  • PP on a model without the mixin. Start-up raises NotImplementedError when the class does not implement SupportsPP ({{cite vllm/config/model.py:1569-1576}}).

Why it matters. A new architecture, a fork of a model, or an out-of-tree model plugin starts with a file like llama.py. Learn the contract, the prefixes and the TP layer classes. Then you can read any model file in vLLM. You can also write a new one that works with quantization, LoRA, PP and torch.compile.

Which two constructor parameters must every vLLM model class have, and who checks them?

vllm_config and prefix. initialize_model() checks the constructor signature by name; without both, it warns and guesses the arguments ({{cite vllm/model_executor/model_loader/utils.py:96-112}}).

 What prefix does the QKV layer of decoder layer 5 get, and which component would break if the prefix were "qkv" only?

model.layers.5.self_attn.qkv_proj (llama.py lines 172, 297, 498 and make_layers). With "qkv", the quantization config would look up the wrong name, for example in FP8's ignored_layers check ({{cite vllm/model_executor/layers/quantization/fp8.py:177-187}}). Weight loading would still work, because AutoWeightsLoader uses the module tree.

 Why does LlamaAttention.forward not pass the KV cache or the attention metadata to self.attn?

The Attention layer registered itself under its prefix in static_forward_context ({{cite vllm/model_executor/layers/attention/attention.py:443-445}}). The runner binds the KV cache by that name. It also sets the metadata in the forward context before each step, so the attention op finds both by the layer name ({{cite vllm/model_executor/layers/attention/attention.py:705-717}}).

 A Llama with 32 layers runs with PP = 2 and TP = 2. How many all-reduces does the first stage do per step, and what does it return?

Stage 0 runs layers 0-15, each with two all-reduces (o_proj, down_proj), plus one in the embedding: 33 (derived from {{cite vllm/model_executor/layers/linear.py:1803-1806}} and {{cite vllm/model_executor/layers/vocab_parallel_embedding.py:558-563}}). It returns IntermediateTensors with hidden_states and residual, each [T, 4096] ({{cite vllm/model_executor/models/llama.py:443-450}}).

 Why is @support_torch_compile on LlamaModel and not on LlamaForCausalLM? Name one consequence.

The decorator wraps the forward of the class it decorates ({{cite vllm/model_executor/models/llama.py:337-347}}). compute_logits is a method of LlamaForCausalLM, so the runner calls it outside the compiled graph of LlamaModel. To sample, it passes only the rows in logits_indices ({{cite vllm/v1/worker/gpu/model_runner.py:1637-1638}}).
